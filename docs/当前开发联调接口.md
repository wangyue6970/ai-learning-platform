# 当前开发联调接口

本文件记录当前已经实现、可用于前后端联调的接口。它不替代《接口文档.md》中规划的 V1 完整接口。

## 图片导入、Word 解析、OCR、AI 草稿与人工确认

以下接口是当前已经在 Android 真机上走通的导入闭环。一个学习库可一次上传任意数量的图片，或上传一个 `.docx` Word 文件；每个文件分别识别、生成草稿和确认，不会因另一张失败而丢失已有结果。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/libraries/{libraryId}/import-batches` | multipart 上传一个或多个文件，创建导入批次和文件记录。字段名为 `files`。 |
| GET | `/api/libraries/{libraryId}/import-batches/latest` | 读取该学习库最近一次导入批次及其每个文件状态，供客户端轮询进度、离开页面后回来继续查看；大 Word 额外返回 `totalChunkCount`、`completedChunkCount`、`generatedDraftCount`、`estimatedQuestionCount`。 |
| GET | `/api/libraries/{libraryId}/import-batches/{importBatchId}/drafts` | 汇总读取一个导入批次内的全部草稿，用于集中查看和逐题确认；此接口不会自动创建正式题目。 |
| POST | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/recognize` | 对单个文件提取文字：图片调用 PaddleOCR；`.docx` 调用 Apache POI 读取普通段落文字。提取结果保存为 `recognitionText`。 |
| POST | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/structure` | 调用服务端配置的 DeepSeek LLM，将识别文字整理为题目草稿。 |
| GET | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/drafts` | 获取当前导入文件产生的草稿，供用户查看。 |
| PATCH | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/drafts/{draftId}` | 保存用户对题型、题干、选项、答案和解析的修改；只更新草稿。 |
| DELETE | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/drafts/{draftId}` | 用户选择不入库：删除临时草稿和选项，不创建正式题目。 |
| POST | `/api/libraries/{libraryId}/import-batches/files/{importFileId}/drafts/{draftId}/confirm` | 用户确认一题，将草稿事务性复制为正式题目。 |
| POST | `/api/libraries/{libraryId}/import-batches/{importBatchId}/drafts/confirm-all` | 用户主动点击“全部入库”后，逐题确认该批次内所有待确认草稿；合格题目入库，缺少答案或不合法的草稿保留并返回失败原因。 |

文件状态：

```text
WAITING_RECOGNITION
→ RECOGNIZING
→ WAITING_STRUCTURING
→ STRUCTURING
→ WAITING_CONFIRMATION
→ CONFIRMED（草稿已正式入库）
```

失败状态为 `UPLOAD_FAILED`、`RECOGNITION_FAILED` 或 `STRUCTURING_FAILED`。失败只影响该文件，前端会展示原因；其他文件仍可继续处理。

当前 `.docx` 只读取用户正常输入的段落文字；旧 `.doc`、Word 表格、内嵌图片和复杂公式暂不支持。大 Word 会按题号拆成最多 10 题一批，每完成一批立即保存草稿和进度；手机轮询的是数据库中的真实批次、草稿数量，不是模拟动画。文件损坏或没有可用文字时，文件进入 `RECOGNITION_FAILED`，不会创建草稿或正式题目。

### 草稿编辑请求示例

```json
{
  "questionType": "SINGLE_CHOICE",
  "stem": "负责选择下一个运行进程的是？",
  "options": [
    { "optionKey": "A", "content": "文件系统", "sortOrder": 1 },
    { "optionKey": "B", "content": "调度程序", "sortOrder": 2 }
  ],
  "correctAnswer": ["B"],
  "explanation": "调度程序负责从就绪队列中选择下一个运行进程。",
  "knowledgePoints": []
}
```

确认入库时，后端再次检查草稿属于当前学习库和当前导入文件、题干和选项不为空、答案属于选项、单选和判断题不含多个答案。确认动作使用数据库事务：创建正式 `question`、创建 `question_option`、草稿标为 `CONFIRMED` 必须全部成功；重复确认会被拒绝。

“全部入库”不是跳过人工确认：用户点击一次即确认该批次内全部草稿。后端仍会对每一题执行相同校验；某一题不合格时不会阻塞其余题目，响应会返回已入库数量和仍需补充的草稿编号及原因。

同一图片或 Word 文件可生成多道草稿。只有该文件的草稿都已经确认入库或明确选择不入库后，后端才删除其临时原文件：有正式题目时文件状态为 `CONFIRMED`，全部不入库时为 `DISCARDED`。删除失败不会撤销已成功入库的题目，接口会返回对应的原文件清理失败提示。

## 获取题目编辑详情

`GET /api/questions/{id}`

用于题目编辑页。返回题干、选项、正确答案和解析；刷题页面仍应调用不返回答案的题目列表接口。

```json
{
  "id": 12,
  "libraryId": 3,
  "questionType": "SINGLE_CHOICE",
  "stem": "负责进程调度的是？",
  "options": [
    { "optionKey": "A", "content": "文件系统", "sortOrder": 1 },
    { "optionKey": "B", "content": "调度程序", "sortOrder": 2 }
  ],
  "correctAnswer": ["B"],
  "explanation": "调度程序负责选择下一个运行的进程。"
}
```

## 保存题目编辑

`PATCH /api/questions/{id}`

用于保存题型、题干、选项、正确答案和解析。题目仍属于原学习库，不能通过此接口修改 `libraryId`。如果正确答案变更，后端会清除该题现有的错题连续答对状态。

```json
{
  "questionType": "SINGLE_CHOICE",
  "stem": "负责进程调度的是？",
  "options": [
    { "optionKey": "A", "content": "文件系统", "sortOrder": 1 },
    { "optionKey": "B", "content": "调度程序", "sortOrder": 2 }
  ],
  "correctAnswer": ["B"],
  "explanation": "调度程序负责选择下一个运行的进程。"
}
```

## 删除题目

`DELETE /api/questions/{id}`

删除题目后，MySQL 会依据外键级联自动删除其选项、作答记录和错题状态。成功时返回 `204 No Content`，即请求成功但没有 JSON 内容。

# 当前认证接口

本文档只记录已经实现并经过自动 HTTP 测试的认证接口。

## 注册

`POST /api/auth/register`

请求体：

```json
{
  "username": "xiaoming",
  "password": "password123"
}
```

成功时返回 `201 Created`：

```json
{
  "id": 1,
  "username": "xiaoming"
}
```

安全规则：

- 不返回 `password` 或 `passwordHash`。
- 用户名会去除首尾空格，长度必须为 2 到 50 个字符。
- 密码至少 8 个字符、不能全为空白、UTF-8 编码不能超过 72 字节。
- 用户名不能重复。

## 登录

`POST /api/auth/login`

请求体：

```json
{
  "username": "xiaoming",
  "password": "password123"
}
```

成功时返回 `200 OK`：

```json
{
  "accessToken": "eyJ...",
  "tokenType": "Bearer",
  "expiresInSeconds": 7200,
  "username": "xiaoming"
}
```

失败规则：

- 用户名或密码为空：返回 `400 Bad Request`。
- 用户不存在或密码错误：统一返回 `401 Unauthorized` 和“用户名或密码错误”；不区分是哪一项错，避免泄露账号是否存在。
- 响应绝不返回 `password` 或 `passwordHash`。

## JWT 请求认证

除注册、登录和健康检查外，所有 `/api/**` 业务接口都必须携带：

```http
Authorization: Bearer {accessToken}
```

后端会验证 Token 的签名与有效期，并确认 Token 对应的用户仍存在：

- 未携带、伪造或过期 Token：返回 `401 Unauthorized` 和“请先登录或重新登录”。
- 用户已被删除但旧 Token 尚未过期：同样返回 `401`，旧登录立即失效。
- 验证通过后，后端将当前 `userId` 放入本次请求的安全上下文，供后续业务层读取。

当前边界：接口已经强制要求有效登录；下一步才会用当前 `userId` 对照学习库的 `owner_id`，限制学习库、导入和题目接口只能访问本人数据。

## 学习库归属校验

学习库接口已经开始使用当前登录用户的 `userId` 与 `learning_library.owner_id` 做匹配：

- `GET /api/libraries`：只返回当前用户自己的学习库。
- `POST /api/libraries`：新学习库的 `owner_id` 由后端写为当前用户，客户端不能指定主人。
- 查看、改名、删除某个学习库：只有该学习库主人可以操作；其他已登录用户收到 `403 Forbidden` 和“无权访问该学习库”。

当前边界：学习库本身已经隔离；题目、刷题、错题和图片/Word 导入会在后续步骤复用同一归属校验。

## 当前手机客户端行为

- 登录成功后，客户端用 Expo SecureStore 加密保存 accessToken 和用户名；不保存密码。
- App 重启时会先恢复本地 token；未保存 token 时只显示登录页。
- 学习库、题目和导入请求统一通过客户端请求层自动附加 `Authorization: Bearer {accessToken}`。
- 当前后端尚未强制验证该请求头；JWT 解析和学习库归属校验将在下一小步启用。

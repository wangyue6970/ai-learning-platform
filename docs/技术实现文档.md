# **AI 学习平台 V1**

> 功能、前端、后端、扫描识别、数据正确性与测试设计

> **技术选择：**V1 不训练自有模型。OCR 与 LLM 通过 Adapter 调用；本地开发默认使用 PaddleOCR 与 Ollama 本地 Qwen，后续可替换为云服务。React Native 与 Spring Boot 保持单体开发节奏。

## **1. 技术栈**

| **层** | **V1 选型** | **用途** |
| --- | --- | --- |
| 移动端 | React Native CLI + TypeScript | Android App；相机/相册/文档选择、上传、刷题界面。 |
| 前端状态 | React Navigation、TanStack Query、Zustand | 导航、接口缓存与局部界面状态。 |
| 安全存储 | react-native-keychain | 保存 accessToken / refreshToken，禁止 AsyncStorage 明文存令牌。 |
| 后端 | Java 17 + Spring Boot + Spring Security | REST API、认证、业务服务、后台任务。 |
| 数据 | MySQL 8、Redis | MySQL 是事实来源；Redis 做缓存、限流、锁和令牌撤销辅助。 |
| 文件 | MinIO（开发）/ S3 兼容对象存储（部署） | 临时导入文件；私有桶和生命周期清理。 |
| AI | OCR Provider Adapter + LLM Adapter | OCR 文字/版面提取；LLM 仅提取原文已有的题目结构。 |

## **2. React Native 客户端实现**

### **2.1 页面与状态**

| **页面** | **关键实现** |
| --- | --- |
| 资料导入 | 先请求 GET /app-config；选择器限制 1–30 张图片或一个 .docx；客户端显示 SELECTED、UPLOADING、UPLOAD_FAILED。 |
| 导入处理中 | 轮询 GET /imports/{id} 或后续 WebSocket；逐文件显示进度、失败原因、重试入口和草稿数量。 |
| 草稿确认 | 分页加载草稿，支持编辑/丢弃；处理 PARTIAL_SUCCESS 时允许先确认可确认草稿。 |
| 刷题 | 创建会话后只使用 practice 接口题目 DTO；不缓存或展示答案与解析，提交后再渲染结果。 |
| 令牌续期 | 请求 401 时仅发起一次刷新；刷新成功重放原请求，失败则清除安全存储并跳登录。 |
| 继续练习 | 进入刷题设置时调用活动会话查询接口；若返回尚未过期的会话，展示继续练习入口并按该 sessionId 恢复。 |

### **2.2 上传与容量保护**

- 选择图片后可压缩和生成预览，但必须保留足够 OCR 清晰度；上传前按服务端配置检查数量、单文件与总大小。

- 使用 multipart/form-data；每个批次生成 clientBatchId。网络中断时可提示重试，后端用 clientBatchId 去重。

- 不把 OCR、LLM、对象存储的 API Key 放入安装包。

## **3. Spring Boot 模块与异步任务**

| **模块** | **主要职责** |
| --- | --- |
| auth | 注册、登录、刷新/轮换 refreshToken、退出、JWT 解析。 |
| library | 学习库 CRUD、库隔离、删除任务。 |
| importing | 上传校验、批次/文件状态、对象存储、重试、草稿确认、清理策略。 |
| question | 正式题目与选项 CRUD、答案变更规则。 |
| practice | 冻结会话题目、提交答案、答案快照、错题状态转换。 |
| ai | OCR/LLM Adapter、文本预处理、任务切块、结构校验、调用日志、失败分类。 |

异步实现：POST 导入接口先写入 import_batch/import_file 与 Job 记录，再提交任务。Job 状态固定为 PENDING / RUNNING / RETRY_PENDING / SUCCEEDED / FAILED。Worker 从数据库领取任务；任务状态、重试次数、下次重试时间和失败原因持久化。应用重启后，调度器回收超时 RUNNING 任务并重试，避免仅靠 @Async 导致任务丢失。

## **4. 扫描、OCR 与 LLM 设计**

### **4.0 本地免费开发环境**

- OCR：PaddleOCR 在本机运行，图片不发送给云 OCR；它只负责“图片转文字”。
- LLM：Ollama 在 `127.0.0.1:11434` 提供本地 Qwen API；它只将原始文字整理为题目 JSON。
- Java 后端通过 Adapter 调用以上本地服务。AI 返回的数据必须经过 Java 校验并保存为 `question_draft`；不得直接创建 `question`。
- 本机 GPU 驱动不兼容时，可用 `OLLAMA_LLM_LIBRARY=cpu_avx2` 强制 CPU 推理。CPU 模式较慢，但不产生 API 调用费用。
- 生产环境可在不改变草稿确认规则的前提下，将两个 Adapter 替换为云 OCR / 云 LLM。

### **4.1 V1 导入处理链路与职责**

| 步骤 | 执行者 | 实现内容 |
| --- | --- | --- |
| 1. 上传资料 | 客户端 + Java | 上传多张图片或一个 `.docx`；后端校验扩展名、MIME、魔数、尺寸和容量后写入私有对象存储。 |
| 2. OCR 提取文字 | OCR 服务 | 图片输出文字块、位置和置信度；低质量或空文本标记为文件失败。 |
| 3. 文本预处理 | Java | 去空行、去乱码、统一空白和标点、合并分页；这是固定规则，不交给 LLM。 |
| 4. 任务切块 | Java | 按页、最大长度和章节边界拆分为多个可重试的 LLM 任务。 |
| 5. 语义提取 | LLM | 识别题目边界和题型，提取题干、选项、原文已有答案和原文已有解析。 |
| 6. 结构化草稿 | LLM | 按约定输出严格 JSON，不输出说明性文字。 |
| 7. 业务校验 | Java | 校验 JSON、题型、选项、答案与必填字段；区分可重试的任务错误和等待用户补充的字段缺失。 |
| 8. 用户确认 | 用户 | 修改、补充或丢弃草稿。 |
| 9. 正式入库 | Java | 仅将用户确认后的草稿事务性写入 question / question_option。 |

图片在 OCR 前可做纠偏、裁边、压缩和去噪；处理期间保留原图以便用户确认。V1 的 `.docx` 使用 Apache POI 读取段落、表格和嵌入图片；文本进入同一预处理/切块链路，嵌入图片走 OCR。旧 `.doc` 不支持。

### **4.2 LLM 输出、禁止项与校验**

```json
{"questions":[{"type":"SINGLE","stem":"题干","options":[{"key":"A","text":"选项"}],"answer":["A"],"analysis":"原文已有解析或 null","sourceFileId":"if_01"}]}
```

- LLM 只从资料原文提取信息：不猜答案、不生成解析、不生成知识点、不改写题目。原文没有答案或解析时，字段为 `null`；前端必须提示用户补充后才能确认。

- Java 使用 JSON Schema 与 Bean Validation 校验：type 只能为 SINGLE / MULTIPLE / JUDGE；答案必须存在于选项中；判断题必须符合布尔选项规则。无法解析的 JSON、未知题型和不符合规则的答案不能入草稿；字段缺失但题目其余内容可读时可生成待补充草稿。

- 记录 OCR/LLM 的供应商、模型版本、耗时、请求关联 ID、重试次数和失败原因；不在日志中长期保存完整敏感原文。V2 再评估置信度评分与重点检查提示。

## **5. 数据模型与事务**

| **表** | **关键字段与约束** |
| --- | --- |
| import_batch | user_id、library_id、processing_status、confirmation_status、client_batch_id（用户库内唯一）、expires_at。 |
| import_file | batch_id、source_object_key、file_status（UPLOADED / PROCESSING / SUCCEEDED / FAILED / EXPIRED）、retry_count、expires_at、failure_reason；草稿必须可追溯 source_file_id。 |
| import_draft_question | batch_id、source_file_id、version、discarded、content_json、confirm_token；草稿版本变化使旧 token 失效。 |
| question | library_id、type、stem、answer_json、analysis、content_version、updated_at。 |
| practice_session | user_id、library_id、scope、question_type、expires_at、status、random_seed。 |
| practice_session_question | session_id、question_id、sequence_no、answered；唯一(session_id, question_id)。 |
| answer_record | user_id、library_id、session_id、question_id、client_answer_id、selected_answers_json、is_correct、answer_snapshot、created_at；唯一(user_id, client_answer_id)。 |
| user_question_state | user_id、library_id、question_id、wrong_state、consecutive_correct；唯一(user_id, library_id, question_id)。 |

提交答案事务：锁定作答幂等键 → 写入 answer_record → 更新 user_question_state → 更新 session_question 已答状态 → 返回结果。确认导入事务：校验 confirmToken 与 clientConfirmId → 创建正式题目 → 标记草稿已确认 → 写入确认记录；重复 clientConfirmId 返回首次结果。

## **6. 安全、删除与清理**

- 密码使用 BCrypt / Argon2 哈希；accessToken 2 小时，refreshToken 30 天并支持轮换和注销撤销。

- 所有库内查询带 user_id 与 library_id 条件；服务层做二次校验，不能只依赖前端路由。

- 取消立即删除临时对象；失败文件保留 24 小时；未确认草稿与必要源文件保留 7 天；确认后立即删除已确认源文件。

- 删除学习库用后台删除任务与审计日志；数据库删除与对象存储清理通过事务外盒/补偿任务保证最终一致。

## **7. 测试与上线检查**

| **测试类型** | **必须覆盖** |
| --- | --- |
| 单元测试 | 错题两次连续答对、答错归零、答案修改重置、幂等提交、Token 轮换。 |
| 集成测试 | 跨学习库越权、导入部分成功与重试、确认幂等、分页、删除任务。 |
| 端到端 | 3–30 张图片与一个 .docx 导入、草稿修改确认、按题型练习、退出后继续会话。 |
| 真机测试 | Android 相册/文件权限、弱网和中断上传、后台回到前台、令牌过期续期。 |

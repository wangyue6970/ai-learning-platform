# 当前数据库结构

本文档记录已由 Flyway 迁移、实际创建到本地 MySQL 的表结构；不记录本机密码、JWT 密钥或用户真实数据。

## app_user

认证模块的用户身份表。注册和登录接口已经实现；登录成功后会签发 JWT accessToken。

| 字段 | 类型 | 规则 | 用途 |
| --- | --- | --- | --- |
| id | BIGINT | 主键、自增 | 用户唯一身份 |
| username | VARCHAR(50) | 非空、唯一 | 用户登录账号 |
| password_hash | VARCHAR(100) | 非空 | BCrypt 生成的密码哈希，绝不保存原密码 |
| created_at | DATETIME | 自动写入 | 注册时间 |
| updated_at | DATETIME | 自动更新 | 最后修改时间 |

## 学习库归属

`learning_library` 已增加 `owner_id`，外键关联 `app_user.id`。

- 每个学习库必须属于一个用户；题目、导入、作答和错题通过 `library_id` 间接归属于同一用户。
- V10 迁移会创建本地开发用的 `demo-user`，并将已有学习库归入该账号，避免已有测试数据丢失。
- 当前迁移只补齐数据归属；真正通过登录用户限制接口访问，会在 JWT 鉴权完成后启用。

## 导入文件实时进度

`import_file` 除了保存文件状态和识别原文外，还保存大 Word 的真实生成进度。前端只读取这些持久化字段，不自行模拟进度。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| total_chunk_count | INT | 当前 Word 被按题号拆成的总批数；普通图片为 0。 |
| completed_chunk_count | INT | 已被本地 LLM 成功处理并保存草稿的批数。 |
| generated_draft_count | INT | 已实际写入 `question_draft` 表的草稿数量。 |
| estimated_question_count | INT | 从 Word 题号开头检测到的题目数量，仅作原文规模提示。 |

每完成一批，题目草稿和以上计数会一起写入 MySQL。因此用户离开导入页再回来，仍能看到已完成批数和已生成题数；这些字段不会把草稿直接写入正式题库。

## 当前密码处理

- 后端通过 `PasswordConfig` 统一提供 BCrypt `PasswordEncoder`。
- 注册时使用 `encode` 生成 `password_hash`；登录时使用 `matches` 校验密码。
- 当前已实现注册 HTTP 接口、登录 HTTP 接口和 JWT accessToken 签发；JWT 解析与接口权限限制将在下一步启用。
- 注册用户名会去除首尾空格，长度必须为 2 到 50 个字符，且不能重复。
- 注册密码至少 8 个字符、不能全为空白、UTF-8 编码不能超过 72 字节。

## 当前后端映射

- `AppUser` 实体把 Java 的用户对象映射到 `app_user` 表。
- `AppUserMapper` 继承 MyBatis-Plus `BaseMapper`，提供用户表的基础增查改删能力。
- Mapper 只处理数据读写；用户名校验、注册和登录业务规则由 `AuthService` 处理。

# **AI 学习平台 V1**

> 从资料导入到可刷题题库的系统边界与数据流

> **架构原则：**V1 使用 React Native Android + Spring Boot 单体 + MySQL + Redis + S3 兼容对象存储。导入在单体内异步处理，不提前拆分微服务。

## **1. 总体架构**

系统分为 Android 客户端、Spring Boot 单体后端、数据与缓存、临时对象存储、OCR/LLM 适配层五部分。OCR 负责识别，Java 后端负责固定规则与校验，LLM 负责语义理解，用户负责最终确认；AI 不直接创建正式题目。

| **层** | **主要职责** | **关键约束** |
| --- | --- | --- |
| React Native Android | 登录、学习库、文件选择与上传、草稿确认、刷题和错题集。 | 不保存 AI 密钥；刷题前不接收正确答案。 |
| Spring Boot 单体 | 认证、学习库、导入任务、文本清洗与切块、草稿、题目、练习、错题、删除任务。 | 所有库内请求验证 userId + libraryId；所有规则性处理留在后端。 |
| MySQL | 业务事实来源：用户、库、批次、文件、草稿、题目、会话、记录、错题状态。 | 以事务和唯一约束保障确认、作答幂等。 |
| Redis | 短期缓存、刷新令牌撤销标记、限流、分布式锁。 | 不能成为唯一业务事实来源。 |
| 对象存储 | 仅保存导入期间的临时原文件。 | 按确认、取消、失败和过期策略清理。 |
| OCR / LLM Adapter | OCR 输出文字与版面结果；LLM 从原文提取结构化题目草稿。 | 供应商可替换；LLM 不猜答案/生成解析；JSON 必须校验。 |

## **2. 核心数据流**

### **2.1 导入与确认**

1. App 调用 GET /app-config 获取当前可上传的文件类型、数量与大小限制，再选择多张图片或一个 .docx。

1. App 以 multipart/form-data 上传；后端验证扩展名、MIME、文件头、单文件大小、总大小和所属学习库。

1. 后端写入 import_batch、import_file 和对象存储对象，返回批次 ID；后台 Job 按文件执行以下内部链路：

   1. 图片经 OCR 转为文字、版面位置与置信度；`.docx` 由 Apache POI 读取文本/表格，内嵌图片走 OCR。
   2. Java 清理空行和乱码、统一格式、合并分页，并按页、长度或章节切成 LLM 任务。
   3. LLM 只识别题目边界、题型并提取原文已有的题干、选项、答案与解析，输出严格 JSON。
   4. Java 校验 JSON 格式、题型、选项与答案规则；格式不合法的任务进入失败/重试，缺少原文答案或解析的草稿保留空字段等待用户补充。
   5. 校验通过的结果写入可编辑草稿，绝不直接写入正式题库。

1. 用户分页查看草稿，修订或丢弃草稿。POST confirm 用 confirmToken 与 clientConfirmId 在一个事务内创建正式题目。

1. 确认后的源文件立即删除；失败文件可保留 24 小时重试；未确认草稿最多保留 7 天。

### **2.2 部分成功处理**

| **处理结果** | **processingStatus** | **用户下一步** |
| --- | --- | --- |
| 全部成功 | READY_FOR_CONFIRM | 查看、编辑并确认草稿。 |
| 部分成功 | PARTIAL_SUCCESS | 可先确认成功文件的草稿；失败文件在 24 小时内单独重试。 |
| 全部失败 | FAILED | 查看失败原因；在 24 小时内重试或重新上传。 |
| 取消 / 过期 | CANCELLED / EXPIRED | 临时文件已清理；如仍需要，重新创建导入批次。 |

## **3. 领域模块与数据关系**

| **模块** | **核心表** | **关系与职责** |
| --- | --- | --- |
| 认证 | user、refresh_token | 用户身份、刷新令牌轮换与撤销。 |
| 学习库 | study_library、library_deletion_task | 库是数据隔离边界；删除采用删除任务和审计日志。 |
| 导入 | import_batch、import_file、import_draft_question | 批次/文件级状态、草稿来源追踪、确认版本。 |
| 题库 | question、question_option | 确认后的正式题目；题目变更保留版本与答案快照语义。 |
| 练习 | practice_session、practice_session_question、answer_record | 会话在创建时冻结题目顺序；提交答案幂等。 |
| 错题 | user_question_state | 按用户、学习库、题目维度维护连续答对次数与状态。 |

> **关键隔离：**question、answer_record、user_question_state、practice_session 都必须直接或可验证地归属同一 libraryId；任何通过 questionId、sessionId、importId 访问的接口都要回查所属库与当前用户。

## **4. 刷题与错题架构**

创建练习会话时，后端按范围（ALL / WRONG）和题型（SINGLE / MULTIPLE / JUDGE）查询可用题目，随机并持久化为 practice_session_question。会话有效期 24 小时，期间不重新抽题。用户进入学习库的刷题设置时，App 查询该库尚未过期的活动会话；存在则用返回的 sessionId 恢复练习。

| **接口阶段** | **返回数据** |
| --- | --- |
| 开始练习 / 获取当前题 | sessionId、进度、题干、题型、选项；不含 answer、analysis。 |
| 提交答案 | isCorrect、correctAnswers、analysis、下一题标识、错题状态变化。 |
| 题目管理 | 可返回完整题目详情（含答案）；该接口不得被刷题流程调用。 |

## **5. 可靠性与安全**

- 导入任务采用数据库持久化 Job，状态为 PENDING / RUNNING / RETRY_PENDING / SUCCEEDED / FAILED；服务重启后由调度器扫描 RUNNING / RETRY_PENDING 任务并恢复，不能只依赖内存 @Async。

- import_file、answer_record、confirm 请求均有幂等键或版本检查，避免网络重试造成重复处理、重复创建题目或错误计数翻倍。

- 上传文件做白名单、魔数校验、容量校验、访问私有化、短期签名访问；OCR/LLM 密钥只在服务端保存。

- 删除学习库由后台删除任务执行，先停止新请求，再事务删除数据库关联，随后清理对象存储并写入审计日志。
